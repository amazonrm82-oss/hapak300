# כשירות חפ״ק מח״ט 300 — המערכת האמיתית

מימוש ייצור של האב-טיפוס שנבנה ב-Claude Design (`../project/`), לפי המפרט ב-`../project/design_handoff_hapak300/`.

**Next.js 14 (App Router) + TypeScript + Supabase** — נתונים משותפים לכל המשתמשים, הרשאות שנאכפות בבסיס הנתונים, התראות אמיתיות, ואפליקציה להתקנה בטלפון (PWA).

> האב-טיפוס בתיקיית `project/` נשאר כמו שהוא ואינו חלק מהמערכת הזו — הוא המקור לעיצוב ולכללים, לא קוד שרץ.

## 2. הקמת בסיס הנתונים (כ-15 דקות)

### 2.1 יצירת הפרויקט
1. היכנס ל-Supabase → **New project**.
2. בחר אזור **Frankfurt (eu-central-1)** — הכי קרוב.
3. שמור את סיסמת בסיס הנתונים במקום בטוח.

### 2.2 העלאת הסכמה
מתוך תיקיית `app/`:

```bash
supabase login
supabase link --project-ref <PROJECT-REF>     # ה-REF מופיע בכתובת הדשבורד
supabase db push                               # מריץ את כל הקבצים ב-supabase/migrations
```

ואז את נתוני הפתיחה — בדשבורד, **SQL Editor**, הדבק את התוכן של `supabase/seed.sql` והרץ.

זה יוצר: ההגדרות, שני הצוותים, עשרת נושאי האימון עם הוראות הבטיחות, מאגרי הציוד/הרכבים/הנשק — ו**שני אנשים בלבד**:

| שם | מספר אישי | תפקיד |
|---|---|---|
| רס״ן מתן זזון | `8409505` | מנהל מערכת |
| סרן ישראל קדוש | `7387250` | מפקד החפ״ק |

**אין אימונים ואין נתוני דמו.** את הלוחמים ואת סבב האימונים מזינים מתוך המערכת.

### 2.3 הסודות של פונקציות הכניסה
בדשבורד: **Edge Functions → Secrets**. הוסף:

```
PIN_PEPPER          = <מחרוזת אקראית ארוכה>
AUTH_DERIVE_SECRET  = <מחרוזת אקראית ארוכה אחרת>
SITE_URL            = https://<הכתובת של האתר>
```

ליצירת מחרוזות אקראיות:

```bash
openssl rand -base64 48
```

> **חשוב**: `PIN_PEPPER` הוא מה שמגן על קודי הכניסה אם מישהו משיג עותק של בסיס הנתונים. אל תשנה אותו אחרי שלוחמים כבר בחרו קודים — כל הקודים יפסיקו לעבוד ויהיה צריך לאפס את כולם.

### 2.4 העלאת הפונקציות

```bash
supabase functions deploy auth-login
supabase functions deploy auth-set-pin
supabase functions deploy run-automations
```

## 5. הפעלת האוטומציות (תזכורות)

התזכורות רצות כל 10 דקות בצד השרת. ב-**SQL Editor** הרץ פעם אחת, עם הערכים שלך:

```sql
select cron.schedule(
  'hapak-automations',
  '*/10 * * * *',
  $$
  select net.http_post(
    url     := 'https://<PROJECT-REF>.supabase.co/functions/v1/run-automations',
    headers := jsonb_build_object(
                 'Content-Type', 'application/json',
                 'Authorization', 'Bearer <SERVICE_ROLE_KEY>'),
    body    := '{}'::jsonb
  );
  $$
);
```

מה זה שולח:
- **ערב לפני, 18:00** — תזכורת עם שעת היציאה ונקודת האיסוף.
- **שעתיים לפני היציאה** — תזכורת בוקר.
- **יום אחרי אימון שעבר** — ״ממתין לסיכום״ למפקדים.
- **הזמנה ללא מענה מעל 48 שעות** — התרעה למפקד עם הצעת מחליף.
- **הסמכה שפוקעת ב-30 הימים הקרובים** — ללוחם ולמנהלים.

כל התרעה נשלחת **פעם אחת בלבד** (טבלת `reminders_sent`).

### התראות פוש לטלפון (רשות)

```bash
npx web-push generate-vapid-keys
```

- ה-**public key** → `NEXT_PUBLIC_VAPID_PUBLIC_KEY` ב-Vercel.
- ה-**private key** → `VAPID_PRIVATE_KEY` בסודות של Supabase, יחד עם `VAPID_PUBLIC_KEY` ו-`VAPID_SUBJECT`.

כל לוחם מפעיל את ההתראות פעם אחת בכל מכשיר, מתוך **פרופיל → הגדרות התראות**.

## 6. הפעלה ביחידה — סדר הפעולות

1. **כניסה ראשונה** במספר האישי שלך, בחירת קוד.
2. **צוותים** → הוספה מהירה: שם, דרגה, תפקיד, מספר אישי, טלפון, צוות. אף אחד לא יכול להיכנס עד שהוא נמצא ברשימה הזו.
3. בטופס המלא (**עריכה**) של כל לוחם: הרשאות (מפקד צוות / מדריך / מפקד חפ״ק / מנהל), הסמכות הדרכה לפי נושא, והסמכות אישיות עם תאריך תפוגה.
4. **מנה מפקד צוות** לכל צוות — הוא זה שמאשר נוכחות סופית.
5. **ניהול → יצירת סבב אוטומטי**: תאריך התחלה, יום בשבוע, שעות, מספר שבועות סבב ומשותפים, ובחירת הנושאים. המערכת בונה את כל התקופה — ואפשר לערוך כל שורה בטבלה.
6. כל לוחם נכנס במספר האישי שלו, בוחר קוד, ומתחיל לסמן נוכחות.

## 7. איך זה בנוי

```
app/
├── src/
│   ├── app/                      מסכים (App Router)
│   │   ├── login/                כניסה — מספר אישי + קוד
│   │   ├── (app)/                כל המסכים אחרי הכניסה
│   │   │   ├── schedule/         ציר התקופה + פירוט השבוע  ← מסך הבית
│   │   │   ├── trainings/[id]/   מסך אימון: 5 לשוניות
│   │   │   ├── teams/            צוותים, לוחמים, הרשאות, הסמכות
│   │   │   ├── manage/           ניהול התקופה (מנהל / מפקד חפ״ק)
│   │   │   ├── my/  chat/        מסכי הטלפון
│   │   │   └── logistics/ calendar/ archive/ profile/
│   │   └── api/weather/          מזג אוויר לפי נצ״ד (רשת ישראל → WGS84)
│   ├── components/               רכיבים משותפים ודיאלוגים
│   └── lib/
│       ├── core/                 ← כל הכללים העסקיים
│       ├── data/                 טעינה, מוטציות, Realtime
│       └── supabase/             חיבור
└── supabase/
    ├── migrations/               סכמה, RLS, פונקציות, אוטומציות
    ├── functions/                Edge Functions (כניסה + תזכורות)
    └── seed.sql                  מצב פתיחה נקי
```

**`src/lib/core/` הוא הלב.** כל הכללים — הרשאות, סטטיסטיקות נוכחות, התרעות למפקד, הצעת מחליף, חישוב כשירות, יצירת סבב, ייצוא — תורגמו אחד-לאחד מ-`hapak-core.js` של האב-טיפוס. שינוי כלל עסקי מתחיל שם.

### הכללים העסקיים, בקצרה
- **נוכחות** — מגיע / מאחר / לא מגיע / חולה-גימלים / מילואים אחר / סיבה חופשית. סיבה **חובה** כשלא ״מגיע״ או ״מאחר״. פתוח עד תחילת האימון. מי שלא הגיב נרשם ״לא מגיע״ באישור הסופי. ״מאחר״ נספר כמגיע.
- **אישור בשתי רמות** — מפקד האימון מסכם ← מפקד הצוות מאשר. באימון משותף מפקד האימון מאשר הכול. מפקד יכול לפתוח מחדש.
- **מחליף אוטומטי** — מוסמך לנושא +4, זמין באותו יום +2, העביר את הנושא בעבר +2, מהצוות השני +1, ‎−0.3 לכל אימון שכבר העביר בתקופה.
- **כשירות 1–10** — דירוג מפקד 50% · נוכחות מאושרת 25% · נושאים שהושלמו 25%. נראית למפקדים בלבד.
- **סיכום** — רשות; ננעל 7 ימים אחרי האימון (מנהל ומפקד חפ״ק פטורים).
- **תחמושת** — כדורים ללוחם × מספר לוחמים, או סה״כ ישיר; ״נוצל בפועל״ מוזן על ידי מפקד האימון; חתימת מפקד אימון על ההקצאה.

## 8. אבטחה

- **כניסה**: מספר אישי (7 ספרות) + קוד (4 ספרות) שהלוחם בוחר בכניסה הראשונה. הקוד נדרש **בכל כניסה** — הסשן נשמר ב-`sessionStorage` ונעלם עם סגירת הלשונית.
- **הקוד** נשמר כ-PBKDF2-SHA256 (210,000 סבבים) עם מלח אישי ו-pepper שנמצא רק בסביבת הפונקציות. אחרי 5 ניסיונות כושלים החשבון ננעל ל-15 דקות.
- **הסיסמה של Supabase Auth אינה הקוד** — היא נגזרת בשרת ממזהה הלוחם, כך שהקוד לא עוזב את פונקציות הכניסה.
- **הרשאות נאכפות ב-RLS**, לא רק בממשק: כל טבלה מוגנת לפי מטריצת ההרשאות. לוחם רגיל לא יכול לקרוא מספרים אישיים של אחרים גם דרך קריאה ישירה ל-API (`people_view` מסתירה אותם), לא יכול לאשר נוכחות של עצמו, ולא יכול לסמן נוכחות אחרי שהאימון התחיל — טריגרים בבסיס הנתונים חוסמים את זה.
- **איפוס קוד** — מנהל מערכת או מפקד חפ״ק בלבד, מטופס הלוחם.
- **מנהל אחרון** — לא ניתן להסיר את הרשאת הניהול האחרונה במערכת.

## 11. תקלות נפוצות

**״חסרה הגדרת Supabase״** — `.env.local` לא מולא, או שהשרת לא הופעל מחדש אחרי המילוי.

**נכנסים ומיד חוזרים למסך הכניסה** — הסודות `PIN_PEPPER` / `AUTH_DERIVE_SECRET` לא מוגדרים ב-Edge Functions, או שהפונקציות לא הועלו (סעיף 2.4).

**״המספר האישי לא רשום״ למי שכן הוספת** — בדוק שהמספר הוא בדיוק 7 ספרות ושהלוחם בסטטוס ״פעיל״.

**שינוי במכשיר אחד לא מופיע באחר** — Realtime לא מופעל לטבלה. בדשבורד: **Database → Replication** ← ודא שהטבלאות מהמיגרציה `0001` נמצאות בפרסום `supabase_realtime`.

**התזכורות לא נשלחות** — הרץ `select * from cron.job;` ובדוק שה-Routine קיים; ואז `select * from reminders_sent order by sent_at desc limit 10;` כדי לראות מה כבר נשלח.
