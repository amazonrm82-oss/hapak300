# בדיקות בסיס הנתונים

הבדיקות רצות על Postgres מקומי ומאמתות את מה שחשוב באמת: שההרשאות נאכפות
בבסיס הנתונים, ולא רק בממשק. אין צורך בפרויקט Supabase.

```bash
# מריצים כמשתמש לא-root, עם Postgres 16 מותקן
export PATH=$PATH:/usr/lib/postgresql/16/bin
initdb -D /tmp/pgtest -U postgres --auth=trust
pg_ctl -D /tmp/pgtest -o "-p 55432 -k /tmp/pgsock" -l /tmp/pg.log start

createdb -h /tmp/pgsock -p 55432 -U postgres hapak
psql -h /tmp/pgsock -p 55432 -U postgres -d hapak -f supabase/tests/00_supabase_stubs.sql
psql -h /tmp/pgsock -p 55432 -U postgres -d hapak --single-transaction -f supabase/setup.sql
psql -h /tmp/pgsock -p 55432 -U postgres -d hapak -f supabase/tests/01_permissions.sql
```

**הרץ תמיד על בסיס נתונים נקי** — הבדיקות מוסיפות נתונים, והרצה שנייה על אותו
בסיס תיכשל על ספירות ומפתחות כפולים.

## מה נבדק (84 בדיקות)

**סכמה ופעולות** — יצירת אימון עם כל הלוגיסטיקה בקריאה אחת, מספר אימון רץ,
שיבוץ אוטומטי של רכב פינוי וחובש תורן, והתראה לצוות על אימון שפורסם.

**מה מותר למנהל** — הוספת לוחם, עריכתו והסרתו.

**מה חסום ללוחם רגיל** — לראות מספר אישי של אחר, לאשר נוכחות (של עצמו או של
אחרים), לדרג, לסמן נוכחות של לוחם אחר, לרשום ״לא מגיע״ בלי סיבה, ולהעניק
לעצמו הרשאות.

**אישור סופי** — מי שלא הגיב נרשם ״לא מגיע״ אוטומטית, מי שכן סימן שומר על
הסטטוס שלו, ופתיחה מחדש מוחקת רק את הסימונים האוטומטיים.

**סדר הדרגות** — מפקד החפ״ק מנהל את היחידה אבל אינו מנהל מערכת: הוא עורך לוחם
רגיל, ונחסם מלערוך מנהל מערכת, למנות אחד (כולל את עצמו), להוסיף אחד, להסיר
אחד או לאפס לו את הקוד. מנהל מערכת עושה את כל זה, כולל על מפקד החפ״ק.

**הזמנות** — הזמנת מדריך נרשמת, ממתינה למענה, המדריך מאשר והסטטוס עובר
ל״אושר״, ואי אפשר לאשר הזמנה של מישהו אחר. (הבדיקות האלה נוספו אחרי באג
אמיתי: `CASE` מחזיר טקסט, ו-Postgres אינו ממיר טקסט ל-enum מעצמו, ולכן שום
הזמנה לא עבדה.)

**כניסה** — השרת מצליח לשמור את הקוד שהלוחם בחר (בלי זה כל כניסה נראית
ככניסה ראשונה), ולוחם עדיין נחסם מלכתוב לעצמו hash ישירות.

**בקשת הצטרפות** — נשלחת בלי סשן כלל, ובכל זאת מייצרת התראה למנהל המערכת
ולמפקד החפ״ק, לא ללוחם רגיל, עם שם, תפקיד ומספר אישי.

**דיבור בשם היחידה** — לוחם נחסם משליחת התראה ליחידה ומקריאה ישירה ל-`notify`;
מפקד צוות שולח התראה על האימון שלו כרגיל.

**טופס ההצטרפות הפתוח** — בקשה כפולה, מספר אישי שכבר במערכת, ומספר לא תקין
נדחים; ומגבלת הקצב סופרת, חוסמת, ומפרידה בין קוראים.

**ניתוק סשן פתוח** — טוקן שהונפק לפני ניתוק המכשירים נדחה מיד; לוחם שהושבת
מאבד גישה בלי שאיש יעשה דבר; ובשני המקרים גם ה-views המסכות (`people_view`,
`trainings_view`) מפסיקות לענות, למרות שהן רצות כבעליהן ו-RLS אינו חל עליהן.

**יומן הפעולות** — הוספת לוחם, מינוי הרשאה, ניתוק מכשירים ויצירת אימון נרשמים;
ואי אפשר לכתוב אליו ידנית או למחוק ממנו.

**פרטי לוחם** — מפקד מזין נשק אישי ופרופיל רפואי; הלוחם נחסם משינוי שניהם
על עצמו; ומספר הנשק של אחר מוסתר ממנו. הבדיקה של השדות הפרטיים משווה את כל
השורה ולא רשימת עמודות, כך שגם עמודה שתתווסף בעתיד מוגנת מיד.

**סגירת תקופה** — שמורה למנהלים, דוחה תאריך התחלה שאינו אחרי הקודם, שומרת את
התקופה עם שורה לכל לוחם ומספר האימונים, ופותחת את החדשה.

**צוות סדיר** — לוחם סדיר משובץ לאימון של צוות א׳, מזוהה כמשתתף, מסמן נוכחות;
הצוות מסומן `attends_all`; ואי אפשר ליצור אימון ששייך לסדיר בלבד.

לבדיקת קובץ עדכון (`patch-NN-*.sql`) על בסיס קיים: הקם בסיס מ-`setup.sql` של
הגרסה הקודמת (`git show HEAD:app/supabase/setup.sql`), הרץ את הפאץ׳ פעמיים
כדי לוודא שהוא חוזר על עצמו בלי נזק, ואז את הבדיקות.
