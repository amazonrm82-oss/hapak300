# חבילת העברה למפתחים — כשירות חפ״ק מח״ט 300

## סקירה
מערכת ניהול תוכנית אימונים לשני צוותי חפ״ק (צוות א׳, צוות ב׳) של מפקדת חטיבה: לו״ז תקופתי (סבב מדורג — צוות ב׳ עושה את אותו אימון שבוע אחרי צוות א׳, ואז שבועות משותפים), סימון נוכחות על ידי כל לוחם ואישור סופי בשתי רמות (מפקד אימון מסכם → מפקד צוות מאשר), הזמנת מדריך ומפקד אימון עם מענה תוך 48 שעות והצעת מחליף, לוגיסטיקה לכל אימון (ציוד עם צ׳קליסט החזרה, רכבים, תחמושת לפי נשק, מזון ושתייה), צ׳אט לאימון, סיכום וארכיון, יומן מח״ט, הסמכות עם תוקף, משוב לוחמים, וניהול אנשים והרשאות.

## על קובצי העיצוב
הקבצים בחבילה הם **אבות-טיפוס בעיצוב גבוה שנבנו ב-HTML** ומדגימים את המראה וההתנהגות המכוונים — הם **אינם קוד ייצור להעתקה כמו שהוא**. המשימה: **ליישם מחדש את המסכים והלוגיקה בסביבת הקוד של הפרויקט** (מומלץ: React/Next.js או React Native/Expo לאפליקציה, עם Supabase כשרת). הלוגיקה העסקית כולה מרוכזת ב-`hapak-core.js` ומנותקת מהתצוגה — אותה יש לתרגם לשכבת שרת/DB ולפונקציות צד-לקוח.

## רמת נאמנות
**גבוהה (hi-fi).** צבעים, טיפוגרפיה, ריווח, רכיבים והתנהגות סופיים. יש לשחזר במדויק תוך שימוש בספריות הקיימות בקוד.

## תשתית מומלצת — Supabase
- **Auth**: כניסה במספר אישי (7 ספרות) + קוד 4 ספרות שהמשתמש בוחר בכניסה הראשונה. מימוש מוצע: Supabase Auth עם אימייל סינתטי `<pn>@hapak300.local` וסיסמה = קוד; או Edge Function `login(pn, pin)` שמאמתת מול `people.pin_hash` (bcrypt/argon2 — **לא** ה-hash הפשוט שבאב-הטיפוס) ומחזירה JWT מותאם. הקוד נדרש **בכל כניסה** (אין שמירת סשן). איפוס קוד: מנהל מערכת / מפקד חפ״ק בלבד (מאפס ל-NULL → המשתמש בוחר קוד חדש).
- **הרשאה**: תפקידי מערכת — `admin`, `hapak_commander`, `team_commander`, `instructor`, `fighter` (דגלים על `people`). RLS לפי המטריצה בהמשך.
- **Realtime**: מנוי לטבלאות `trainings`, `attendance`, `chat_messages`, `notifications` — כל שינוי משתקף לכל הטלפונים (באב-הטיפוס: אירוע `hapak:changed` + localStorage).
- **Storage**: buckets `training-photos`, `training-orders` (PDF), `chat-attachments`. באב-הטיפוס תמונות נשמרו כ-base64 — להחליף בהעלאה ל-Storage.
- **Cron / Edge Functions**: תזכורות (ערב לפני 18:00, שעתיים לפני היציאה), דגל הזמנה ללא מענה מעל 48 שעות, ״ממתין לסיכום״ למפקד יום אחרי אימון שעבר, התרעת הסמכה 30 יום לפני תפוגה. הלוגיקה קיימת ב-`runAutomations()` ב-`hapak-core.js` — להריץ אותה בצד השרת פעם ב-15 דקות ולשלוח פוש (FCM / Web Push) ובנוסף רשומת `notifications`.
- **יומן המח״ט**: בגרסה זו הזנה ידנית (טבלה `calendar_events`). שלב הבא: סנכרון קריאה-בלבד מ-Google Calendar דרך Service Account / ICS, ב-Edge Function מתוזמנת שמכניסה אירועים עם `source='google'`.
- **מזג אוויר**: באב-הטיפוס הערכה דמה. לחבר ל-Open-Meteo / השירות המטאורולוגי לפי נצ״ד (המרה מרשת ישראל החדשה ל-WGS84). זריחה/שקיעה מחושבים בצד לקוח (`sunTimes`) — תקין.
- **ייצוא**: CSV נוכחות (UTF-8 BOM), PDF נוכחות ופקודת אימון (הדפסה). בשרת: יצירת PDF ב-Edge Function (למשל `pdf-lib`).

## מודל נתונים (טבלאות מוצעות)
- `settings` (שורה אחת): app_name, unit_name, brigade_commander, period_start (date, יום ראשון), period_name, real_mode, allow_join, min_attendance (6), essential_roles (text[] — חובש, נהג, מאבטח), invite_hours (48), evening_reminder ('18:00'), morning_reminder_before (120 דק׳), approval_window_hours (48), cert_alert_days (30), summary_lock_days (7).
- `teams`: id ('a'|'b'), name, commander_id → people.
- `people`: id, team_id (nullable — מפקדה), rank (12 דרגות: טוראי…אל״ם), name, role (מפקד צוות | קמב״צ | קשר | נהג | חובש | מאבטח), pn (7 ספרות, unique), phone, status ('active'|'inactive'), status_note, rating (1–10, דירוג מפקד תקופתי), qual (text[] נושאי הדרכה), is_team_commander, is_instructor, is_admin, is_hapak_commander, pin_hash, pin_set_at, certs (jsonb: {fire, drive, medic, comms, mildrive, medical} → תאריך תפוגה), notif (jsonb: evening, morning, approved, changed).
- `topics`: id, name, safety (תבנית הוראות בטיחות ברירת מחדל).
- `trainings`: id, seq (מספר רץ לפי תאריך בתוך הצוות — מחושב), team_id ('a'|'b'|'joint'), topic_id, date, end_date (nullable), start, end (HH:MM, 24 שעות), location (טקסט חופשי + מאגר), coords (נצ״ד רשת ישראל החדשה, טקסט), instructor_id, commander_id, inst_status/cmd_status ('pending'|'accepted'|'declined'), inst_invited_at/cmd_invited_at, status ('planned'|'published'|'done'|'cancelled'), freq (תדרים), safety, pickup, departure (יציאה = התחלה −90 דק׳), medic_id, evac_vehicle_id, order_file, notes, trainer_summarized, approved_all, ammo_signed/by/at, cancel_reason, summary (jsonb: commander, instructor, keep, improve), created_at, updated_at.
- `day_blocks`: training_id, time, title (התכנסות ומסדר, תדריך בטיחות, הדרכה, תרגול, הפסקת אוכל, סיכום ולקחים, החזרת ציוד וספירה).
- `attendance`: training_id, person_id, status ('coming'|'late'|'absent'|'sick'|'reserve'|'other'), reason (חובה כשלא ״מגיע/מאחר״), marked_at, approved, approved_by, rating (1–10 לאימון), auto (סומן אוטומטית ״לא הגיב = לא מגיע״ בעת אישור).
- `gear_items`: training_id, name, qty, returned, missing (טקסט), owner_id. `gear_catalog`: name.
- `vehicles`: training_id, type (האמר, רוביקון, RZR, …), tz (מספר צ׳), driver_id, seats, departure, fitness ('כשיר'|'טעון בדיקה'|'מושבת'), fault. `vehicle_types`: name.
- `ammo`: training_id, weapon (M4/תבור, נגב, מא״ג, אקדח, מטול רימונים, רימוני רסס, רימוני עשן, סימונים/נורים), per_fighter, allocated (כדורים), used.
- `food`: training_id, name, qty, unit, note.
- `chat_messages`: training_id, author_id, text, time, pinned, read_by (uuid[]), attachment (url, name, is_image).
- `feedback`: training_id, person_id, overall (1–5), instructor (1–5), logistics (1–5), comment, time. נפתח כשהאימון `done`; נראה למפקדים ולמדריך.
- `photos`: training_id, url, by, name.
- `calendar_events`: id, title, date, time, all_day, location, training_id (nullable), note, source ('manual'|'google').
- `notifications`: id, text, time, read (per user — מומלץ טבלת `notification_reads`), to (uuid[] או NULL = כולם), training_id.
- `join_requests`: name, rank, role, pn, phone, team_id, status, at.
- `reminders_sent`: key (text, unique) — מניעת כפילות תזכורות.

## מסכים
### אתר (Hapak Web.dc.html)
1. **כניסה** — מספר אישי (7 ספרות) → שלב 2: קוד 4 ספרות (בכניסה ראשונה: בחירה + אימות; חסימת קודים צפויים כמו 1234 / ספרה חוזרת). הודעת שגיאה ברורה למי שלא רשום. ״בקשת הצטרפות״ (אם מופעל) → ממתין לאישור מנהל. כניסה מהירה למשתמשים — **רק** כשמצב ״הפעלה אמיתית״ כבוי.
2. **לו״ז** (מסך הבית) — באנר ״היום/מחר״ לאימון קרוב עם כפתור סימון נוכחות; ציר התקופה: רשת 72px + עמודה לכל שבוע, שורות צוות א׳ / צוות ב׳, שבועות משותפים ממוזגים לתא אחד (accent-900); לחיצה על שבוע → פירוט: כרטיסי האימונים של השבוע (מיקום, נצ״ד, מדריך ומפקד עם סטטוס אישור, יציאה, תגי לוגיסטיקה, פס נוכחות, התרעות למפקד), יומן המח״ט של השבוע, כשירות צוותים 1–10 (למפקדים).
3. **אימונים** — טבלה; סינון צוות; ״ממתינים לסיכום״ למפקדים.
4. **מסך אימון** — כותרת + פעולות (סימון נוכחות, עריכה, דחייה, ביטול, שיתוף פקודה, פקודה PDF, שכפול, מחיקה, ייצוא). לשוניות: סקירה (פרטים, מדריך/מפקד + הזמן/החלף + ״מעל 48 שעות — מחליף מוצע״, תדרים, מזג אוויר (הערכה), זריחה/שקיעה, חובש ורכב פינוי, פקודת אימון PDF, הוראות בטיחות, לו״ז יום, תזכורות), נוכחות (טבלה, סטטוסים, סיבה, דירוג 1–10, אישור/פתיחה, סיכום מפקד אימון → אישור סופי), לוגיסטיקה (ציוד/רכבים/תחמושת/מזון — כל אחד עם טבלה עריכה והוספה), צ׳אט (נעיצה, נקרא-על-ידי, קבצים/תמונות), סיכום (משוב לוחם, ממוצעי משוב למפקדים, סיכום מפקד/מדריך/לקחים, תמונות, סיום → ארכיון; נעילה שבוע לאחר האימון למעט מנהל).
5. **צוותים** — הוספה מהירה (שם, דרגה, תפקיד, מ.א., טלפון, צוות), התרעות הסמכות, בקשות הצטרפות, שני כרטיסי צוות (ממוינים לפי דרגה, תגי מפקד/מדריך/מושבת, כשירות אישית למפקדים), מפקדה. טופס לוחם מלא: פרטים, סטטוס, **סוג משתמש והרשאות** (מפקד צוות, מדריך, מפקד חפ״ק, מנהל), הסמכות הדרכה לפי נושא, **הסמכות אישיות עם תוקף**, איפוס קוד, הסרה.
6. **לוגיסטיקה** — מבט על לכל האימונים + מאגרי ציוד / סוגי רכבים / מיקומים.
7. **יומן מח״ט** — רשת שבועית א׳–ש׳: אימונים + אירועים (חגים אוטומטיים + הזנה ידנית של מנהל: כותרת, תאריך, שעה/כל היום, מיקום, קישור לאימון, הערה).
8. **ארכיון** — הסתיימו/בוטלו; סינון צוות/נושא/חיפוש חופשי.
9. **ניהול** (מנהל/מפקד חפ״ק) — שם התקופה ותחילתה, יצירת סבב אוטומטי (תאריך, יום בשבוע, שעות, שבועות סבב/משותפים, נושאים, מדורג), הזזת כל הלו״ז, תבנית ריקה, תבנית דוגמה, טבלת כל האימונים בעריכה ישירה (צוות, נושא, תאריך, שעות, מיקום) + שכפול/מחיקה, ניהול נושאים והוראות בטיחות.
10. **פרופיל** — פרטים, כשירות אישית, הסמכות ותוקף, הנוכחות שלי, הגדרות התראות, (מנהל) הגדרות מערכת / איפוס למצב התחלתי.

### אפליקציה (Hapak Mobile App.dc.html, מוצגת ב-Hapak Mobile.dc.html במסגרות iPhone/Android)
לשוניות תחתונות: לו״ז · האימון שלי · צ׳אט · הצוות · פרופיל (+ מסכי לוגיסטיקה וארכיון מהפרופיל). אותה לוגיקה ונתונים כמו האתר; סימון נוכחות בגיליון תחתון (bottom sheet); משוב אחרי אימון; באנר היום/מחר; יעדי לחיצה ≥ 44px.

## אינטראקציות וכללים עסקיים
- **נוכחות**: סטטוסים מגיע / מאחר / לא מגיע / חולה-גימלים / מילואים אחר / סיבה חופשית; סיבה חובה כשלא ״מגיע/מאחר״; פתוח עד תחילת האימון; מי שלא הגיב נחשב ״לא מגיע״ בעת האישור הסופי; ״מאחר״ נספר כמגיע; מפקד יכול לפתוח מחדש.
- **התרעות למפקד**: צפויים מתחת לסף (6 לצוות, 12 במשותף); תפקידים חיוניים חסרים (חובש, נהג, מאבטח); פחות נהגים מרכבים; הזמנות ממתינות/נדחו; רכב לא כשיר; הזמנה מעל 48 שעות; הסמכה שפקעה (אזהרה בלבד); אימון עבר וממתין לסיכום.
- **מחליף אוטומטי**: ניקוד — מוסמך לנושא +4, זמין באותו יום +2, העביר את הנושא בעבר +2, מהצוות השני +1, פחות אימונים שהעביר בתקופה (−0.3 לכל אימון). מוצג המועמד הראשון עם ההצדקה.
- **שינוי אימון**: שינוי תאריך/שעות/מיקום שולח התראה לכל הצוות; **דחייה** מאפסת נוכחות; **ביטול** נשמר בארכיון כ״בוטל״ עם סיבה; **מחיקה** (מנהל) סופית.
- **כשירות 1–10**: דירוג מפקד 50% · נוכחות מאושרת 25% · נושאים שהושלמו 25% (עד שיש אימונים שהסתיימו — לפי דירוג בלבד). נראה למפקדים בלבד.
- **תחמושת**: לפי נשק — כדורים ללוחם × מספר לוחמים = הקצאה, או סה״כ ישיר; ״נוצל בפועל״ מוזן ע״י מפקד האימון; חתימת מפקד אימון על ההקצאה.
- **ציוד**: צ׳קליסט החזרה; דיווח חוסר + אחראי.
- **סיכום**: רשות; נעילה 7 ימים אחרי האימון (מנהל/מפקד חפ״ק פטורים).
- **משוב**: 1–5 כללי / מדריך / לוגיסטיקה + הערה; נפתח כשהאימון ״הסתיים״; לא אנונימי; נראה למפקדים ולמדריך.
- **תזכורות**: ערב לפני 18:00, שעתיים לפני היציאה; כאישור נוכחות; כשאימון שונה — לפי הגדרות המשתמש (notif).
- **תאריכים**: לועזי בלבד, שעון 24 שעות, ימי שבוע א׳–ש׳, מספרי שבועות מתחילת התקופה (יום ראשון).
